# Задача для Codex: Software → Проекты и страницы продуктов

## Контекст
Сайт `PashaPilat-GitSite`: React + Webpack + GitHub Pages. Не переносить проект на Next.js и не переписывать архитектуру без необходимости.

На странице Software уже есть шапка, переключатель языка, фон с зелёным цифровым дождём, заголовок `SoftWare — программные проекты` и кнопка перехода к проектам. Сохранить их и сначала изучить текущую маршрутизацию, компоненты, CSS и локализацию.

## Цель
Создать каталог проектов и отдельные страницы:
- `/software/projects` — каталог;
- `/software/projects/jarvis-ii` — Jarvis II;
- `/software/projects/media-center` — PlatP Media Center;
- `/software/projects/creator-studio` — PlatP Creator Studio.

Это ориентировочные URL. Сначала проверить текущую маршрутизацию и особенности GitHub Pages; адаптировать адреса к существующей схеме и обеспечить корректное прямое открытие вложенных страниц и обновление страницы.

## Визуальное направление
Использовать приложенный скриншот сайта как исходный ориентир, а концепт карточек — как направление дизайна.

- Сохранить текущий Matrix-фон, шапку, навигацию и общий стиль сайта.
- Палитра: почти чёрный, тёмно-зелёный, зелёные акценты, светлый текст.
- Карточки: полупрозрачная тёмная поверхность, тонкая зелёная граница, умеренное свечение при наведении.
- Не перегружать интерфейс неоном и не заменять существующий фон новым.
- При необходимости добавить локальное затемнение под текстом для читаемости.
- Каталог: три карточки в ряд на широком экране, две на среднем, одна на мобильном.
- Каждая карточка: крупное превью одинакового соотношения сторон, название, статус, короткое описание, теги и ссылка `Подробнее ↗`.
- Наведение — лёгкое усиление границы/свечения и небольшое движение превью. Учитывать `prefers-reduced-motion`.
- Изображения не растягивать. Использовать локальные ассеты, которые позже легко заменить реальными скриншотами.
- Не придумывать статистику, рейтинги, количество пользователей или иные неподтверждённые данные.

### Jarvis II

Превью: футуристичный интерфейс ассистента с AI-ядром и элементами управления Windows. Концепт не выдавать за скриншот готового приложения.

### PlatP Media Center
Описание: «Медиацентр для организации фильмов, сериалов, музыки, клипов и личной медиатеки.»
Теги: `Media` · `Desktop` · `Library`
Статус: `В разработке`
Превью: тёмная библиотека с постерами и боковой навигацией. Если в репозитории есть реальные скриншоты, предпочесть их концепту.

### PlatP Creator Studio
Описание: «Инструмент для анализа видео, подготовки публикаций и организации YouTube-контента.»
Теги: `YouTube` · `AI` · `Creator Tools`
Статус: `В разработке`
Превью: тёмная панель с аналитикой, видеопревью и элементами процесса подготовки контента. Не показывать вымышленные показатели как реальные данные приложения.

## Общая структура страницы проекта
1. Хлебные крошки: `Software / Проекты / Название`.
2. Кнопка возврата к каталогу.
3. Первый экран: название, краткое описание и крупное превью.
4. Статус разработки.
5. Раздел «О проекте».
6. «Основные возможности» — направления проекта, без утверждения, что всё уже реализовано.
7. «Технологии» — указывать только подтверждённые технологии; планируемые обозначать отдельно.
8. «Статус разработки» — отличать готовое от запланированного, если это известно.
9. Ссылки на другие проекты внизу страницы.

Не придумывать ссылки на репозитории, демо, загрузки или документацию. Добавлять их только если действующие URL найдены в проекте или предоставлены явно.

## Содержание страниц

### Jarvis II
«Jarvis II — интеллектуальный ассистент для Windows, созданный как дополнительный уровень взаимодействия с операционной системой. Он объединяет голосовое управление, диалоговый интерфейс, системные инструменты и отдельные приложения в модульную экосистему PlatP.»

Основные направления: голосовое взаимодействие, AI-чат, запуск приложений и интеграция с Windows, работа с информацией и файлами, подключаемые модули, инструменты мониторинга и обслуживания системы.

Концепция: Jarvis II не заменяет Windows, а расширяет способы взаимодействия с ней. Ядро ассистента и модули должны развиваться независимо.

### PlatP Media Center
«PlatP Media Center — самостоятельный медиацентр для организации и просмотра личной медиатеки: фильмов, сериалов, видео, музыки, клипов и изображений.»

Основные направления: организация медиатеки, определение типа контента и извлечение сведений из имён файлов, работа с локальными метаданными и онлайн-источниками, поиск и сортировка, продолжение просмотра, фоновое сканирование и обработка очередей, пропуск повторной тяжёлой обработки неизменённых файлов там, где это реализовано.

### PlatP Creator Studio
«PlatP Creator Studio — настольное приложение для упрощения подготовки и организации YouTube-контента: от анализа видео и транскрибации до оформления и планирования публикаций.»

Основные направления: анализ видео, локальная транскрибация с Whisper, помощь в подготовке названий/описаний/тегов, организация плейлистов, подготовка обложек, планирование публикаций и интеграция с YouTube API.

Планируемый технологический подход: Electron, React, Vite, FFmpeg, локальный Whisper и абстракция AI-провайдеров. Не представлять все интеграции как завершённые.

## Локализация
Проверить существующую поддержку русского и английского языков. Добавить новые тексты в текущую систему локализации, если она используется. Не ломать переключатель языка и не смешивать языки на одной странице.

## Технические требования
- Сначала изучить код и назвать конкретные файлы, которые планируется менять.
- Сохранить React + Webpack.
- Не делать несвязанный рефакторинг и не добавлять крупные библиотеки ради простых карточек.
- Повторно использовать существующие компоненты, стили и переменные.
- Обеспечить адаптивность, семантическую разметку, клавиатурный focus и читаемый контраст.
- Не ломать другие разделы, фон, навигацию и GitHub Pages.
- Не добавлять фиктивные кнопки/ссылки.
- Если превью отсутствуют, сделать аккуратные локальные заглушки, которые легко заменить.

## Проверка результата
1. Запустить доступные проверки и сборку.
2. Проверить каталог на широком и мобильном экранах.
3. Проверить переходы на все страницы и возврат в каталог.
4. Проверить прямое открытие URL и обновление страниц с учётом GitHub Pages.
5. Проверить переключение языка.
6. В отчёте перечислить изменённые файлы, выполненные проверки и известные ограничения.

## Порядок работы
Сначала осмотреть проект и дать краткий план с конкретными файлами. Затем реализовать каталог и страницы в рамках текущей архитектуры. Не начинать с переписывания сайта целиком.
